# 英国 VAT 注册程序：Kimi 交接与后续计划

更新日期：2026-09-20。接手时先读项目根目录的 `AGENTS.md`、`README.md`，再按本文推进。

## 1. 当前状态

项目用 Python 3.11+、FastAPI、Playwright 驱动本机 Chrome，完成资料提取、人工确认、HMRC 填表、验证码输入和最终复核。资料提取在本地运行，不调用外部 AI。

**已完成：**程序启动与登录页检查、国家默认值问题排查、改进方案讨论。本次仅补充交接文档，未实现多国家改造。

**下一目标：**支持中国内地、香港、爱尔兰及其他海外公司的资料处理，分别识别公司、个人、税号和手机号的国家／地区，消除错误默认值。国家字段正确不代表所有公司类型的 HMRC 分支都已兼容。

本次验证基线：165 个单元测试通过；流程覆盖检查为 84/84。覆盖检查只验证截图页面有规则映射，不代表真实申请全部验证通过。

## 2. 启动与日常检查

在项目根目录执行：

```bash
# 英国 VAT 网页程序
.venv/bin/vat-web --config vat-config.flow.json
# 地址：http://127.0.0.1:8765
```

销售交付工作台是另一个入口：

```bash
.venv/bin/vat-bench --uk-vat-config vat-config.flow.json
# 地址：http://127.0.0.1:8770
```

使用已有账号登录；无账号时按启动终端的初始化提示创建管理员。前台启动用 `Ctrl+C` 停止。启动前可用 `lsof -nP -iTCP:8765 -sTCP:LISTEN` 检查端口，已有服务则直接访问。不要在客户任务运行中重启服务。

新环境安装步骤见 `README.md`。Web 使用 `vat-config.flow.json`，命令行字面量配置使用 `vat-config.example.json` 的副本，两者不要混用。

已验证：资料袋的 `country`、`home_country` 均为 `Ireland` 时，两处地址页会用 `Ireland`，但海外税号国家页仍返回 `China`。地址资料的优先级高于全局 Country，所以不能只修改全局默认值。

历史案例：2026-09-09 用 AB10913 授权表原样提取，公司国家为 `Ireland`、个人国家为 `China`。2026-09-20 在原指定文件夹下未找到该 DOCX，本次仅重新验证了配置匹配结果。回归测试应使用虚构资料，不依赖客户原件。

## 4. 推荐的数据处理方式

保留已有字段，最小范围扩展：

| 信息 | 字段 | 来源 |
| --- | --- | --- |
| 公司注册国家／地区 | `company_registration_country` | 公司注册资料 |
| 公司注册地址国家／地区 | `country` | 公司地址及人工确认 |
| 个人居住国家／地区 | `home_country` | 居住地址及人工确认 |
| 海外税号所属国家／地区 | 新增 `overseas_tax_identifier_country` | 对应税号资料及人工确认 |
| 验证码手机号国家／地区 | `HMRC_MFA_PHONE_COUNTRY` | 实际手机号及人工选择 |

- 国家识别顺序：该字段明确填写的国家 → 该地址中明确出现的国家 → 留空请用户补充。来源冲突时提示确认，不相互覆盖。公司注册地可作为地址或税号国家的待确认建议，不作为自动填表事实。
- 使用一套共享的国家／地区映射，兼容中文、英文及代码，如中国／China／CN、香港／Hong Kong／HK、爱尔兰／Ireland／IE。香港单独映射到 HMRC 的 Hong Kong 选项。填写时匹配当页实际选项；无法唯一匹配就停止。无需为此引入外部 AI 服务。
- 国家代码只在国家字段或明确地址片段中识别，避免把普通地址中的短词误当国家；其他国家同样允许人工选择，不只支持上述三地。
- 公司注册号和海外税号独立保存，保留字母、前导零及原始格式。取消无条件复制；是否有税号必须明确确认，“没有”与“尚未填写”分别处理。
- 手机号国家提供选择，可根据明确国际区号提示，但不能根据公司或个人地址推断。英国手机号选项与国家选择保持一致。
- 地址保留原文并允许人工编辑结构化字段。支持爱尔兰字母数字邮编，以及表单允许邮编为空的情况；不生成虚假邮编。现有地址字段长度保护继续保留，不能静默截断。
- 新字段需贯通解析别名、`FIELD_DEFINITIONS`、`VAT_REGISTRATION_FIELD_KEYS`、资料袋、两个网页入口及工作台保存流程；旧资料缺字段时显示待补充。

## 5. 后续实施顺序

### P0：消除国家和税号误填

1. 增加共享国家归一化逻辑，移除个人地址与缺失国家的 China 默认值；已有明确的 China 资料仍正常处理。
2. 删除流程表的全局国家兜底；地址页继续用 `doc:home`、`doc:business`。税号国家页改读独立字段，同步 JSON 与 `screenshot_flow.py`。
3. 移除两处“注册号自动当税号”的回填，增加税号有无及所属国家的确认。
4. 两个网页入口加入手机号国家选择和新字段展示。将必要校验放在共用后端，覆盖首次启动、工作台启动、暂停修改后继续；前端同步提示。
5. 更新旧测试中依赖错误默认值的断言，并补充下节案例。运行记录应能定位缺失字段，但不记录凭据或完整客户资料。

完成标准：国家按各自资料传递；缺失、冲突或未确认的信息不会被默认值掩盖；首次启动和继续运行均受校验保护。

### P1：完善国际地址和资料确认

完善中英文地址拆分、爱尔兰邮编、可选字段校验和公司号码标签。对于不能可靠拆分的地址保留原文，请用户修正；人工修正后须重新确认。更改国家或清空字段后，要验证资料袋旧值确实失效，防止继续运行时沿用旧资料。

### P2：验证不同公司类型的流程分支

通过本地模拟页面和经授权的人工联调检查 HMRC 分支。记录适用公司类型与未覆盖页面，遇到未知流程停止。固定营业额、SIC、英国／非英国公司分支属于另一层业务规则，单独核对，不能因国家识别改造而直接宣称全面兼容。

## 6. 验收案例与检查命令

至少补充以下自动化案例，覆盖解析、配置匹配和两个入口的后端校验：

| 案例 | 预期 |
| --- | --- |
| 中国公司＋中国居住地址 | 明确资料归一化为 China，保留现有正确行为 |
| 香港公司＋中国居住地址＋香港手机号 | 三类国家分别传递，Hong Kong 不被覆盖 |
| 爱尔兰公司＋爱尔兰居住地址 | 地址保持 Ireland，支持字母数字邮编 |
| 其他海外公司或税号所属国与公司注册地不同 | 使用独立字段，不被 China 或公司注册地覆盖 |
| 国家缺失、冲突或无法匹配 | 明确提示；必要资料未确认时不运行 |
| 只有公司注册号／明确没有税号／尚未回答 | 三种状态正确区分，不自动生成税号答案 |
| 表单允许邮编为空；长地址；英国手机号 | 条件校验、长度保护、手机号分支正确 |
| 暂停后修改、清空国家或税号；加载旧资料 | 重新确认并校验，旧值不残留 |
