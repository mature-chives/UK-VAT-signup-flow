# 单用户 Web 的公司自动关联与办理隔离

## 需求与边界

- 不再展示“我的客户”或要求手动新建/选择客户。主流程是选择 VAT/EORI → 上传解析 → 核对资料（同时确认公司关联）→ 开始注册。
- 公共公司索引与私有申请空间分开：公司索引只保存名称、注册地、编号类型、编号及成立日期；登录用户 → 私有归属 ID → VAT/EORI → 每次办理记录。公司索引匹配不授予读取别人凭据、证件、个人资料或完整申请记录的权限，管理员也不例外。
- 内地使用 `CN:USCC:18位统一社会信用代码`，检查字符和校验位；香港使用 `HK:BRN:8位号码`，须明确编号类型。只对明确 BRN 的 `XXXXXXXX-XXX-XX-XX-X` 完整证书格式取前 8 位，保留前导零。旧 CRN、任意长数字、VAT 号、GG 号、公司名称及项目编号不作为自动关联唯一键。司法辖区不从通讯地址推断。
- 解析和预览不写公共索引。确认时重新检查：唯一编号且公司名称（仅忽略大小写/空白/标点）一致，成立日期无冲突才关联；冲突需修正或明确选择独立申请，不覆盖旧档案。缺号、未知编号类型、校验不通过时仍可独立办理，不阻塞于建档。格式检查不等同于官方真实性核验。
- 资料确认只需一次点击：正常时按钮为“确认资料无误”；预览发现冲突时保留冲突提示，按钮改为“确认资料，作为独立申请保存”，不再额外勾选。修改公司身份字段后重置该选择；后端仍重新判断冲突，不会静默合并或覆盖公司。
- 共有索引支持按名称或编号检索；“使用公司基础信息”只预填基础字段，不自动导入个人资料/登录账号。重复确认同公司、同用户复用私有空间；不同用户的私有空间始终不同。并发确认在存储锁内去重。
- 同一用户、同公司跨业务复用自己的凭据；资料按业务保存，可从另一业务恢复待核对初稿。证件、浏览器配置、复核文件、结果仍按用户/公司/业务隔离。
- 非运行状态重新上传或修改公司身份字段时，清除旧绑定、账号输入及本页证件引用；确认后再加载属于当前用户和公司的凭据。运行中不能改换公司，旧标签页操作还需匹配办理记录 ID。
- 仍然全服务一次一个自动化任务。切换页面不停止任务；本人可从“我保存的申请（继续办理）”或活动任务链接返回。其他用户只能看到资源忙，不返回申请所属人及客户姓名。
- 每次重试产生独立记录；只复用同客户同业务会话，默认仍使用全新浏览器。复核文件不覆盖旧记录。
- 旧 hmrc-credentials.json 原样保留，不自动按项目编号/用户名认领。不回退到全局 HMRC_USER_ID；共用密码等显式配置仍允许作为最低优先级默认值。客户变更 GG 号时必须提供对应密码，不能拼接旧密码。
- 历史记录不含密码、验证码或明文 GG 号。重启前仍活动的记录显示“服务中断，结果待核实”，不自动重提。
- 旧手动客户档案保留为私有历史，不扫描、不自动公开、不删除；新确认产生的公司基础索引才可检索。旧 HTTP 新建接口保留兼容，但新界面不调用。

## 结果判定

- 执行状态（运行中/结束/停止/失败）与 HMRC 业务结果分别保存。
- 只有识别到 HMRC 明确接收申请的回执页才显示“申请已接收，等待处理”，不能等同于注册获批。
- 只有明确的 EORI 分配成功页及有效 GB EORI 编号才能显示“已取得 EORI”。其他页面即使跳离复核页，也显示“结果待核实”。
- 停止或网络异常不能撤回已发出的请求。记录保留提交确认标志及回执证据；重试前提醒核实，不自动重试。
- 历史复核文件只通过已认证、校验客户和办理记录归属的接口下载，不开放数据目录。

## 验收

直接上传无需建档步骤；USCC 校验位、BRN 前导零及证书格式正确；旧 CRN/模糊编号不误关联；冲突不覆盖；缺号可独立办理；共享搜索不含私有字段；跨用户/伪造 ID/同编号不同业务均不串凭据或资料；刷新恢复已保存初稿；旧数据不自动公开；中断结果不误报成功；停止和正式提交人工确认边界不变。使用虚构资料及模拟接口验证，不访问真实 HMRC。

范围仅为 vat-web。多人工作台 vat-bench 的共享客户协作模型不在本次改动范围内。
