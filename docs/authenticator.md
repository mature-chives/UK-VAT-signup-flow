# Authenticator 自动管理

适用于 `vat-web` 的英国 VAT / EORI 流程。无需引入 AI，也不向外部服务发送二维码或密钥。
页面适配依据 `materials/authenticator/` 的 7 张截图；这些截图含真实认证材料，不能提交或分享。

## 使用

1. 上传资料，核对信息并确认公司归属。
2. 在 HMRC 登录区勾选「自动管理 Authenticator（动态验证码）」。默认不勾选，保留原有人工 / 短信流程。
3. 新 GG 仍需开户邮箱、姓名、密码；可同时使用邮箱池自动收取建号邮件验证码。不再要求开户验证手机号，但申请里的业务联系手机号仍须填写。
4. 开始任务：选择 Authenticator → 安装说明 → 设置密钥 → 6 位动态码 → 命名 `Registration assistant` → 官方绑定成功页。
5. 以后选择已有 GG，并再次勾选开关；同一用户、同一公司、同一 GG 可跨 VAT / EORI 复用密钥。其他用户或公司不会共享。

首次绑定时，操作页会直接显示临时二维码和手机添加提示，并标注公司、GG 尾号。用户用手机 Authenticator 扫码即可；不要求输入手机验证码、点击确认，也不记录「手机备份未验证」状态，自动注册照常继续。
二维码从设置页读取并交叉核对后展示，不从历史密钥重新生成。手机和服务器持有同一份密钥，能否登录仍以 HMRC 本次绑定成功为准。

展示期限为生成后 5 分钟；关闭卡片、停止或结束任务、退出登录都会释放服务端图片引用。切换公司、离开页面或切换到后台标签页时清除当前页面的图片和临时 Blob URL；返回时只在原展示期内重新读取，不能续期。
图片接口要求登录、当前公司的权限、CSRF 和本次任务 ID；仅允许 HTTPS 或本机回环访问，响应禁止缓存。普通状态接口只返回图片是否可用、GG 尾号和剩余展示时间，不返回二维码数据或密钥。
二维码含长期登录密钥，请勿截图、转发或分享屏幕。关闭展示不会撤销已经扫描的密钥；本功能不保证用户已经完成添加。

已有 GG 如果只在手机上绑定过、本机未保存密钥，会转为人工输入，不读取手机，也不会自动新增、替换或解绑验证器。
目前只在新建 GG 流程自动开始绑定；不给已有 GG 自动补绑。
本功能未增加工作台或命令行入口的开关。

## 页面与失败边界

- 仅在 HTTPS Government Gateway 官方域名的 `/multi-factor/` 页面操作，并匹配已确认的页面文案和控件标签，不绑定 CSS class。
- QR 在本机内存中解码，读取标准 `otpauth://totp` 参数，并与页面 `Secret key` 交叉核对；不从任意文本猜测密钥。
- 提交首次动态码前先保存为 `pending`；只有本次绑定走过命名页并识别到官方成功提示后，才标记 `active`。跳离页面本身不算绑定成功。
- 每轮任务只自动提交一次动态码；再次出现验证码页时允许人工输入，不反复试码。接近过期或同一时间窗口已用过时，等待新窗口，停止按钮仍有效。
- 密钥缺失、不同密钥冲突、页面变化、解密失败、时钟回退均不会触发重新绑定或覆盖密钥。
- 若中断留下 `pending`，不会在下次登录时直接拿它自动填码。需管理员核实原绑定是否完成；当前没有自助恢复、导出或强制激活按钮。保留原数据，不要删库重建，也不要重复建号。
- 服务器需要正常时间同步；偏差较大时 HMRC 会拒绝动态码。
- 最终 `Check your answers` 仍须人工核对并明确确认提交。

## 私有存储与备份

启用时自动准备存储，不需要把种子填进 `.env`、`accounts.json` 或 HMRC 普通凭据文件。

| 文件 | 内容 | 权限 |
| --- | --- | --- |
| `.authenticator-key` | AES-GCM 主密钥 | 0600 |
| `.authenticator/vault.sqlite3` | 加密的 TOTP 种子及绑定状态 | 0600，父目录 0700 |

数据库记录由「用户公司凭据归属 + GG 账号」定位；密文的认证附加数据也绑定该记录，不能换账号直接复用密文。
界面显示绑定状态及首次绑定期间的临时扫码卡片；日志不记录种子、二维码或动态码。二维码图片仅放内存、不写办理记录或磁盘；认证整页不生成真实截图 / PDF，而使用遮盖占位图。
自动管理与浏览器录制互斥，并要求全新临时浏览器会话，避免旧会话账号串用或认证页面进入持久浏览器缓存。

停掉注册任务后备份数据库和主密钥，分别限制访问；缺一不可。不要删除或重建主密钥，否则已存种子无法解密。
清除普通 HMRC 登录信息不会删除 Authenticator 密钥，避免无意丢失第二因素。
数据库和主密钥都在同一服务器上，因此这属于自动化托管，**不等同于独立手机设备的第二因素隔离**；获得服务器控制权的人可能获得两种凭据。

## 验证状态

更新服务后需由操作人验证首次绑定、成功提示及后续登录；不要将页面覆盖等同于真实注册成功。
